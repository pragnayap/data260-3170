# HW5 Part 3 - Tool contracts under stress

Generated by `code/mcp_servers/tool_contracts.py`. Input schemas are read from the live MCP tool definitions; error outputs are the actual return values of the rejected calls captured in Part 2B.

Every tool answers with the same envelope, `{ok, data, error}`, defined once in `code/mcp_servers/envelope.py` and reused by `execute_tool` in Part 4. A rejection is a value, not an exception: `ok` is false, `data` is null, and `error` carries the reason.


## `search_incidents`

Search transit incidents by route or location.

### Expected JSON input schema

```json
{
  "properties": {
    "query": {
      "title": "Query",
      "type": "string"
    },
    "limit": {
      "default": 10,
      "title": "Limit",
      "type": "integer"
    },
    "category": {
      "default": "",
      "title": "Category",
      "type": "string"
    }
  },
  "required": [
    "query"
  ],
  "title": "search_incidentsArguments",
  "type": "object"
}
```

### Accepted call

Input:
```json
{
  "query": "Downtown",
  "limit": 5
}
```

Output: `ok: true`, `error: null`, 5 results.

### Rejected JSON input

```json
{
  "query": "Downtown",
  "limit": 0
}
```

### Returned error output

```json
{
  "ok": false,
  "data": null,
  "error": "limit must be between 1 and 50 (got 0)"
}
```

### Why it was rejected

limit is outside the documented range 1-50. A page size of zero has no meaningful result, and leaving it unbounded would let one call ask for the whole table.


## `incident_details`

Look up one incident by its unique code, e.g. INC-3170-00001.

### Expected JSON input schema

```json
{
  "properties": {
    "incident_code": {
      "title": "Incident Code",
      "type": "string"
    },
    "include_submitter": {
      "default": false,
      "title": "Include Submitter",
      "type": "boolean"
    }
  },
  "required": [
    "incident_code"
  ],
  "title": "incident_detailsArguments",
  "type": "object"
}
```

### Accepted call

Input:
```json
{
  "incident_code": "INC-3170-00001"
}
```

Output: `ok: true`, `error: null`.

### Rejected JSON input

```json
{
  "incident_code": "INC-317-1"
}
```

### Returned error output

```json
{
  "ok": false,
  "data": null,
  "error": "incident_code must match INC-NNNN-NNNNN (got 'INC-317-1')"
}
```

### Why it was rejected

incident_code does not match INC-NNNN-NNNNN. The format is checked before any query runs, so a malformed code never reaches the database.


## `incident_stats`

Aggregate incident counts and rider impact.

### Expected JSON input schema

```json
{
  "properties": {
    "group_by": {
      "default": "category",
      "title": "Group By",
      "type": "string"
    }
  },
  "title": "incident_statsArguments",
  "type": "object"
}
```

### Accepted call

Input:
```json
{
  "group_by": "agency"
}
```

Output: `ok: true`, `error: null`.

### Rejected JSON input

```json
{
  "group_by": "banana"
}
```

### Returned error output

```json
{
  "ok": false,
  "data": null,
  "error": "group_by must be one of category, agency, route_type (got 'banana')"
}
```

### Why it was rejected

group_by is not one of the three groupings the tool supports. It maps to a column name, so accepting arbitrary text would be both a wrong answer and an injection surface.
